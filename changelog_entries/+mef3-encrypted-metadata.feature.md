`MEF3RecordingInterface` now reads MEF 3 sessions whose metadata is encrypted, given the session's `password` (either level) or `level_1_password` and `level_2_password`: section 2 is decrypted, and of section 3 only the recording time offset and GMT offset, never the subject's name, ID or recording location; a password that does not validate raises an error naming the file and the level, never the password. Passwords are keyed as meflib keys them (at most 15 characters, the low byte of each code point) and are left out of the extractor's `to_dict()`. The new `MEF3RecordingInterface.get_channel_sampling_frequencies` gives each channel's rate from one metadata file per channel, for converting a session recorded at several rates one rate at a time with `channels_to_skip`. Decryption needs `cryptography`, which the `mef` extra now installs; encrypted data blocks are still refused. Channels left out with `channels_to_skip` still set the session's start time and keep their records, so one interface per rate written through one `ConverterPipe` shares a timeline and one set of records, and each rate's `runs` rows name the rate.
