`EDFRecordingInterface` now supports discontinuous EDF+ (`EDF+D`) files, which were previously rejected outright and which neither SpikeInterface's reader nor `pyedflib` beneath it can open. `EDF+D` is detected from the header and read with a pure-Python/NumPy reader that recovers each data record's true start time from the time-keeping annotations in the `EDF Annotations` signal. Each contiguous run of records becomes its own `ElectricalSeries` at its real start time, sharing one electrodes table, with `runs` and `annotations` `TimeIntervals` tables alongside (disable with `write_runs=False` / `write_annotations=False`). Samples are read lazily, so memory does not scale with file size. The reader tolerates writers that never NUL-terminate a TAL and only NUL-pad the tail of the annotations block, as Nihon Kohden's export does; that tolerance engages only for a file that does not parse under the spec alone and terminates no TAL anywhere, so a conformant file is read by the spec and nothing else. Where a record's time-keeping annotation is genuinely unreadable, the start time is derived from the neighbouring records whenever they span exactly the records in between, warning rather than refusing the file. The recording exposes `physical_unit`, `gain_to_physical_unit` and `offset_to_physical_unit` per channel, as the SpikeInterface path already did, so code that checks the header's declared unit against an external source such as a BIDS `channels.tsv` works on continuous and discontinuous files alike, and an auxiliary channel written as a `TimeSeries` carries its real unit instead of `n.a.`. Plain EDF and `EDF+C` files are unaffected and still read via SpikeInterface. See the [gallery page](https://neuroconv.readthedocs.io/en/main/conversion_examples_gallery/recording/edf.html) for details.
