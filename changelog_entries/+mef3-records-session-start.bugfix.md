`MEF3RecordingInterface` now reads a MEF 3 record file whose writer stored its times offset by the session's start, instead of by the recording time offset the blocks are stored against, from that start. Before, every such record fell far outside the session (decades before it when the offset is far from the start), and one stored as 0 was written as minus the session's start. A file is read this way only when the two readings cannot be confused: every time is stored offset, every one read with the recording time offset falls outside the session by more than its length, and every one read from the start falls within it. The session's span is taken over every channel, kept or skipped, so complementary `channels_to_skip` read the same records. The session warns how many records were read this way. A record time stored as 0 is now read as the time its file counts from (meflib's writer stores a time equal to the recording time offset as 0) rather than as the epoch. A stored `UUTC_NO_ENTRY` is now returned as it is, as meflib returns it, and a record whose own time is `UUTC_NO_ENTRY` is left out of the `records` table with a warning.
